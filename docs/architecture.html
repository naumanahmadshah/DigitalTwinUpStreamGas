Gas Upstream Digital Twin - Architecture

Data flows left to right: synthetic OT and IT sources are generated into Unity Catalog, refined through a bronze - silver - gold medallion (serverless Lakeflow / DLT), and served to a single-page application, a Genie space and an AI/BI dashboard. Every emitter is driven by one seeded field state, so the marts reconcile across production, reliability, emissions and commercial views.

Step 6
Serving and consumption
How users and agents access it
Digital twin app
FastAPI + single-page UI. Reads the gold marts through a SQL warehouse (pooled, concurrent).
Genie space
natural-language analytics over the gold marts only.
AI/BI dashboard
published summary of production, reliability and emissions.
Lakebase write-back ←
the app writes accept / reject / annotate decisions to a Postgres instance (audited).
AREA-SYSTEM-CLASS-NNNN
One join key ties it all together. Every tag id (for example CPF002-CMP-AT-1018) decodes to its area, system and equipment class, and resolves through the backbone to its asset, functional location, live value and its ids in every other system (PI historian, EAM, OSDU, P&ID). The app's Asset & Document Explorer demonstrates this resolution live.

Compute

Everything runs on serverless: the generation job, the Lakeflow medallion pipeline, the SQL warehouse behind the app / Genie / dashboard, and the Lakebase instance.

Governance

All objects live in one Unity Catalog catalog and schema. Tables and columns carry COMMENTs; the app service principal is granted read access on the schema.

Parameterized

Catalog, schema, warehouse and Lakebase instance are bundle variables, so one asset bundle deploys to any workspace with a single command.

Graceful degradation

Without Genie the copilot shows a "not wired yet" note; without Lakebase the recommendation inbox is read-only. The core twin still serves.
